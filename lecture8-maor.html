01

התקנת סקיל מ-SKILLS-IL ב-Claude

סקיל = חבילת הוראות מוכנה שמלמדת את Claude לבצע משימה חוזרת באותה צורה בכל פעם
מה זה נותן: במקום לכתוב כל פעם פרומפט ארוך, מעלים פעם אחת סקיל שמגדיר איך מכינים דוח כספי ישראלי, ומאותו רגע Claude יודע לעבוד לפיו.
  1. בוחרים סקיל באתר. נכנסים לספריית הסקילים בעברית, מחפשים ״דוחות כספיים״, פותחים את ״דוחות כספיים ישראליים״ וקוראים מה הסקיל עושה.
  2. מורידים את הסקיל כקובץ ZIP. מגיעים אל ״איך להשתמש בסקיל הזה״, בוחרים Claude.ai או Claude Desktop לפי סביבת העבודה, לוחצים ״הורדת ZIP״ ושומרים את הקובץ.
  3. מוסיפים את הסקיל ל-Claude. Customize → Skills → + → Create skill → Upload a skillמעלים את קובץ ה-ZIP ומוודאים שהסקיל מופיע כפעיל. לפני ההעלאה: בהגדרות Capabilities מפעילים הרצת קוד ויצירת קבצים.
  4. מפעילים ובודקים. פותחים שיחה חדשה ומבקשים משימה שמתאימה לסקיל, למשל:
    ״השתמש בסקיל israeli-financial-reports. הכן טיוטת דוח רווח והפסד בעברית לעסק לדוגמה. הצג בנפרד נתונים חסרים והנחות.״
    בודקים שהסקיל מופיע כפעיל ושהתוצר מתאים לנתונים ולבקשה.

שימו לב

טיוטה, לא דוח. בדוגמה הפיננסית התוצר הוא טיוטה לבדיקה ולא דוח שהוגש. מי שחותם הוא עדיין אתם.
נתונים פיקטיביים בלבד. את התרגול עושים על עסק לדוגמה, לא על נתוני החברה שלכם.
המסלול העדכני. הורדת ZIP והעלאה דרך מסך הסקילים, לפי מרכז העזרה הרשמי של Claude (קישור בסוף הדף).
02

התקנת Ollama ושיחה עם מודל מקומי

Ollama = תוכנה שמריצה מודל שפה על המחשב שלכם, בלי לשלוח את השיחה לשרת חיצוני
מה זה נותן: מודל מקומי עובד גם בלי אינטרנט והנתונים לא עוזבים את המחשב. בתמורה הוא קטן וחכם פחות ממודל ענן, ותלוי בזיכרון ובחומרה שיש לכם.
  1. מתקינים את Ollama ב-Windows. נכנסים לעמוד ההורדה הרשמי, בוחרים Windows ומעתיקים את פקודת PowerShell שמופיעה באתר. פותחים PowerShell, מדביקים ולוחצים Enter:
    PS>irm https://ollama.com/install.ps1 | iex
    אפשר גם להוריד את מתקין Windows מהאתר ולהשלים התקנה גרפית.
  2. בודקים את ההתקנה. פותחים חלון PowerShell חדש ומריצים:
    PS>ollama --version
  3. בוחרים מודל מקומי. פותחים את עמוד Gemma באתר Ollama, בוחרים את הדגם המקומי ומעתיקים את פקודת ההרצה כפי שהיא:
    PS>ollama run gemma4:e2b
    גודל ההורדה: 7.2 GB. הזיכרון הדרוש תלוי במודל, בחלון ההקשר ובחומרה.
  4. שיחה ראשונה עם המודל. ממתינים לסיום ההורדה הראשונה. כשמופיע שדה ההודעה כותבים למשל:
    ״הסבר בעברית פשוטה מהו מודל שפה מקומי, ותן דוגמה לשימוש בו בשיעור.״
    תשובה שמופיעה במסוף מאשרת שהמודל מגיב. ליציאה מהשיחה וחזרה ל-PowerShell:
    >>>/bye

שימו לב

מסוף (Terminal). חלון טקסט שבו מקלידים פקודות למחשב. ב-Windows קוראים לו PowerShell. כל הפקודות בדף מוקלדות בו באנגלית, משמאל לימין.
חלון הקשר. כמות הטקסט שהמודל ״זוכר״ בשיחה אחת. ככל שהוא גדול יותר, נדרש יותר זיכרון.
מתי זה מתאים למנהל כספים: ניסוח, סיכום ותרגול על חומר רגיש שאסור להעלות לענן. לניתוח כבד עדיין עדיף מודל ענן.
03

התקנת Hermes והגדרת ספק ומודל

Hermes = סוכן AI בקוד פתוח של Nous Research: הוא מקבל משימה, מפרק אותה לשלבים ומפעיל כלים כדי לבצע אותה
איך זה בנוי: המודל (מקומי או בענן) הוא ה״מוח״ שחושב; Hermes הוא המנהל שמריץ את המשימה ואת הכלים. הסוכן יכול לעבוד עם קבצים, לשמור זיכרון בין שיחות וליצור סקילים למשימות חוזרות. מתקינים דרך Ollama, ובהמשך מחברים למודל בענן דרך OpenRouter.
  1. מתקינים דרך Ollama. מוודאים ש-Ollama מעודכן, פותחים PowerShell חדש ומריצים:
    PS>ollama launch hermes
    אם Hermes חסר, הפקודה מציגה בקשה להתקין אותו: בוחרים Yes בעזרת מקשי החצים ולוחצים Enter. המתקין מוריד את הרכיבים, מתקין Python ויוצר סביבת עבודה. ממתינים לסיום; אין צורך להפעיל ידנית את סביבת Python שמוזכרת בפלט.
  2. המסלול המקומי (אופציונלי). בבורר המודלים בוחרים מודל מקומי שמתאים לחומרת המחשב ותומך בכלים, ממתינים להגדרת החיבור האוטומטית, בשירותי ההודעות בוחרים Skip, ומתחילים במשימה קטנה בתיקיית תרגול. אחרי הודעת ההצלחה יוצאים מהבורר עם Esc; Hermes נשאר מותקן.
  3. הגדרה מלאה עם OpenRouter. פותחים PowerShell חדש, מריצים את האשף ובוחרים Full setup (בהדגמה: אפשרות 2):
    PS>hermes setup
    האשף מציג היכן נשמרות ההגדרות ומחיל ברירות מחדל. ואז, בסדר הזה:
    • ספק: OpenRouter (אפשרות 3). שירות שמחבר את הסוכן למאות מודלים בענן דרך חשבון אחד.
    • מפתח API: מזינים מפתח אישי מ-openrouter.ai/keys. בהדגמה הוזן מפתח דמה, ולכן לא ניתן היה להריץ משימה בענן.
    • מודל: anthropic/claude-haiku-4.5 (אפשרות 6). אפשר לבחור מודל אחר מהקטלוג; זמינות ומחירים משתנים.
    • סביבת מסוף: Local (אפשרות 1). המודל פועל בענן, אבל הפקודות והקבצים מטופלים במחשב שלכם.
    • שירותי הודעות: משאירים הכול ללא סימון ולוחצים Enter. חיבור Telegram או WhatsApp הוא שלב אופציונלי (hermes setup gateway).
    • כלים: משאירים פעילים חיפוש, דפדפן, מסוף, קבצים והרצת קוד, וגם סקילים, תכנון משימות, זיכרון, חיפוש שיחות, שאלות הבהרה והאצלת משימות. מסירים כלים שאינם נדרשים לתרגול.
    • דפדפן: Local Browser (אפשרות 1). חיפוש: DuckDuckGo (אפשרות 4), ללא מפתח נוסף.
  4. מפעילים, משנים, עוצרים. אחרי ההגדרה, פקודת ההפעלה השוטפת היא hermes. לשינוי ספק, מודל או מפתח:
    PS>hermes setup model
    האשף מפעיל תהליך רקע (Gateway) גם כשלא נבחר שירות הודעות. בסיום העבודה עוצרים אותו ובודקים שאינו פועל:
    PS>hermes gateway stop

שימו לב

מפתח API הוא סיסמה. לא משתפים, לא מצלמים ולא מדביקים בשיחות. הודעת ״נשמר״ באשף אינה בדיקת תקינות של המפתח.
תיקיית תרגול מוגדרת. נותנים לסוכן משימות רק בתוך תיקייה ייעודית, לא על קבצי העבודה האמיתיים. סוכן עם כלי קבצים ומסוף יכול לשנות ולמחוק.
ההדגמה במפגש. במחשב ההדגמה נדרש תיקון נתיב משתמש קצר יותר לפני ההתקנה. בהתקנה שמסתיימת כרגיל פשוט ממשיכים לשלב הבא.
04

בניית אפליקציה ישירות באתר Lovable

Lovable = שירות שבונה אפליקציית ווב מתיאור בשפה חופשית, ומפרסם אותה בקישור
מה זה נותן: כלי פנימי קטן (מעקב משימות, טופס, מחשבון) בלי מתכנת ובלי לכתוב קוד. בדוגמה מהמפגש: מנהל משימות לימוד בעברית, עם נתוני תרגול פיקטיביים.
  1. מתארים את האפליקציה. נכנסים ל-lovable.dev ומתחברים. מתארים בעברית את האפליקציה ואת הפעולות הרצויות, מבקשים ממשק בעברית ובכיווניות מימין לשמאל, ושולחים.
  2. בודקים את התוצאה הראשונית. לאחר הבנייה, התצוגה המקדימה בעורך מאפשרת להשתמש באפליקציה ולבדוק שהיא עושה מה שביקשתם.
  3. משפרים ובודקים שוב. בודקים פעולה אמיתית (למשל הוספת משימה), מבקשים בצ׳אט שינוי ממוקד ובודקים שוב. בודקים גם תצוגת נייד ואת הכיווניות בעברית.
    דוגמת בקשת שינוי: ״הוסף סינון למשימות של השבוע הקרוב״
  4. מפרסמים ומקבלים קישור. Publish → בדיקת הכתובת והגדרות הגישה → Publishמעתיקים את הקישור ובודקים שהוא נפתח. אחרי שינוי נוסף מעדכנים את האתר החי דרך Publish → Publish changes.

שימו לב

הגדרות גישה. לפני הפרסום בודקים מי יכול לפתוח את הקישור. אפליקציה עם נתונים פנימיים לא מפרסמים לכולם.
שינוי אחד בכל פעם. בקשה ממוקדת קלה לבדיקה; בקשה של עשרה שינויים בבת אחת קשה לאמת.
